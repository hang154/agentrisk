## 재현 및 남은 범위

별도 상태·원장 재구성 840건, 원시 API 호출 3944건 검증 PASS. 독립성은 10개 의미적 업무군으로 보수적으로 처리했습니다. 800번을 독립 표본 800개로 세지 않았습니다.

사람 블라인드 이중 검토, 적응형 공격자·여러 세션·다중 에이전트 조직 실험, RiskQuote 구성요소 분해는 이 최소 V1의 완료 항목이 아닙니다. 과거 Voice 불일치 원인은 별도 감사 표에 연결했습니다.

긍정적 결과 여부와 실행 완료를 구분합니다. 이 연구로 고객 권한 승인·원화 보험료·사람 판정을 생성하지 않았습니다.

## 해석에 필요한 추가 수치

B4−B0의 위험 차이는 −5%p이지만, 사전에 지정한 10개 업무군 exact 검정의
p=.125, 두 주 비교 Holm 보정 p=.25입니다. Bootstrap 구간만 골라 성공으로
바꾸지 않았습니다. 주 비교인 B4−B2는 Holm p=1입니다. B3와 B4는 정상 완료
79/80·위험 실행 2/160으로 집계가 같아, 결과 갱신의 추가 효과도 입증되지 않았습니다.

모니터의 실제 위험 표본은 조건마다 동일한 **5개 행동**입니다. M0의 96건,
M1의 75건 보류를 오답·정상으로 치환하지 않았습니다. M2−M0의 사후 탐색적
paired Brier 차이는 −0.26686, 10개 업무군 bootstrap 95% 구간
[−0.31928, −0.21412]입니다. 구조화 형식 자체(M2−M2_PROSE)와 과거 영수증의
추가 효과(M3−M2)는 각각 구간이 0을 포함했습니다.

홀드아웃으로 표시한 4개 업무군의 공통 B0 제안 206개에서는 연구 점수 Brier
0.24133, GBDT 0.25055, LR 0.29630, 단순 Beta 0.51032입니다. 전체 B0 제안
491개 중 계약 위반은 35개입니다. 개발용 반례는 균형 표본이므로 이 점수를
고객 사고확률로 직접 사용하지 않습니다. 업무군별 재표집 구간과 reliability
bin은 `CALIBRATION_AND_SCORE_SENSITIVITY.json`에 사후 탐색 분석으로 분리했습니다.

## 실행·검증·백업

- 본실험 800/800회, 248.56초, 분당 193.11회. 원시 API 호출 3,751건.
- 별도 파일럿 40회, 사후 모니터 800건, 처리량 진단 3,072호출은 서로 다른 분모입니다.
- 상태 재구성은 파일럿 포함 840회·API 3,944호출, 별도 모니터 감사 800호출 PASS.
- 변조·시드 변경·선행 시점 위조를 넣은 6개 음성 검사를 모두 거부했습니다.
- 로컬/원격의 건수와 판정은 정확히 일치합니다. Python 3.10/3.12 부동소수점
  차이의 최대값은 7×10⁻¹⁵였으며, 재현 검사는 정수·판정을 정확 비교하고
  실수에만 절대오차 10⁻¹²를 허용합니다. 원본 결과는 수정하지 않았습니다.
- 전체 원시 증빙 48,539파일을 압축·해시 검증해 SSD와 별도 HDD에 보존했습니다.
  NAS는 할당량 초과로 쓰기가 거부되어 미완료로 기록했습니다. 기존 NAS 파일은 삭제하지 않았습니다.
- GitHub 공개 패키지는 신규 합성 실행·모니터·진단 원시 요청/응답과 재현 코드를 포함합니다.
  과거 Voice의 비공개 검토 원문과 호스트 운영 로그는 별도 보관합니다.
